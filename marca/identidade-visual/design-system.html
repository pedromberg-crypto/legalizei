A arquitetura em 2 camadas

A tela nunca escolhe uma cor. Ela pede um papel. Isso não é preferência estética — é governança mecânica.

Camada 1 · Primitivos --p-*

São CSS vars comuns. Não entram no @theme, então o Tailwind não gera classe utilitária pra eles. bg-coral-500 simplesmente não existe. Privados: nenhuma tela toca.

Camada 2 · Semânticos --color-*

Só estes viram classe. A tela pede bg-surface-card, text-primary, action-primary — um papel, nunca um matiz. Toda regra de marca fica embutida no mapeamento.

Atrito mecânico. Governança solo é mecânica, não social — ninguém revisa o Pedro às 23h de uma sexta. Então fazer a coisa errada precisa ser mais difícil que fazer a certa. Se #F2643C não existe em lugar nenhum pra copiar, ninguém usa. O caminho curto é o token, por preguiça, não por disciplina.

01
Nenhuma tela toca primitivo
Tela que escreve #F2643C é bug, não estilo.
02

Coral e vermelho são hues vizinhos. Erro = crimson + ícone + texto. A distinção vem da forma, não do matiz.

Gradiente

Uma família gráfica escura, já usada nas telas — não é enfeite novo. Gradiente aqui é acento (hero, card de conteúdo, objeto físico, glow), nunca superfície de UI nem fill de botão. A regra do coral segue: coral cheio não vira fundo de ação.

Raio — derivado do logo

O símbolo tem raio ≈ 0,27 × lado. Num ícone de 44px isso dá ~12 → vira o raio de input/botão. O logo governa o sistema, não é coincidência.

Tema escuro CÓDIGO REAL — no CRM

🔓 31/07 — deixou de ser só proposta: o CRM interno roda 100% no dark (`index.html` trava data-theme="dark", sem toggle — lá dark é o tema, não opção). Os valores viraram fonte canônica no `legalizei/app/src/app/globals.css`, e o `CRM_app/tokens.css` virou espelho declarado (sincroniza à mão, não é build-time ainda). ⚠️ Este app (legalizei, o wizard/portal mobile) continua light-only — o bloco existe como token disponível, nada liga sozinho aqui. Prova viva da arquitetura de 2 camadas: o escuro remapeia só a camada 2 (os --color-*). Os primitivos e todos os componentes ficam intactos. Use o botão Escuro no canto pra alternar e ver o sistema inteiro virar sem nenhum componente mudar.

O que muda (camada 2)

Superfície inverte pra base escura quente (não preto puro, mantém a alma de "papel"). Texto vira warm-white. Tints de estado escurecem e os textos de estado clareiam (o -700 do light é ilegível no escuro). Coral segue mandando na ação.

O que NÃO muda

Zero primitivo tocado. Zero componente reescrito. As 4 regras duras seguem: coral nunca é erro, azul nunca é marca, muted nunca é leitura, tela nunca toca primitivo. Hover ainda escurece.

✔ Contraste verificado (WCAG AA)

Cada par de cor do dark foi medido, não estimado. Texto primário 13,4:1 · secundário 7,7:1 · terciário 4,8:1 · os 4 textos de estado 7,3–9,1:1 · botão grande 3,15:1 (AA-grande) · botão pequeno coral-700 5,64:1. Separação de card no dark vem da borda (hairline forte 1,70:1), não de sombra — é como data-UI escura densa separa tabela e card. text-muted recua de propósito (só placeholder), igual ao light.

Card — tom

Sem sombra por padrão. O tom responde "que tipo de coisa este card é", não "que cor".

neutro

Branco. O padrão. Card de conteúdo.

marca

Coral-50. Destaque suave — não é aviso. Coral nunca é erro.

sucesso

Verde. Boa notícia sobre dinheiro ("abrir é grátis"), não estado de processo.

Tradeoff assumido: o verde é token de estado (nasceu pra estado do CNPJ). Gastá-lo como destaque de venda cobra um preço. Aceito só porque "abrir é grátis" é a única promessa financeira irrefutável. Um terceiro uso decorativo → revisar.

StatusIcon — o átomo de status

Um vocabulário de 5 estados, unificado. Antes o check verde estava copiado em 5 arquivos. Feito = verde (estado real) · recusa = danger · girando = info · travado = muted. Coral nunca é estado.

feito — passo/CNPJ concluído. Verde = estado de verdade.
girando — a vez é do órgão, não sua. A máquina que você assiste.
a-fazer — existe, está no caminho, ainda não é a vez.
travado — retido (só o boleto pendente liga isto).
!recusa — um órgão parou a fila, a bola está com você.
Unifica o como se desenha um status, não de quem é a vez. Por isso os wrappers seguem separados: a checklist (sua vez de preencher) e o painel/timeline (vez do órgão de processar) têm a agência oposta.

Arquétipos — as situações que se repetem

A pergunta não é "quais componentes preciso", é "quais situações se repetem". Derivado do mapa de ramificações do flow, não inventado.

A1
Pergunta
Input / escolha / toggle. O mais comum. Erro inline, nunca modal.
A2
Veredito 🟢🟡🔴
Estado + rota. Regra de ouro: nunca veredito com baixa confiança.
A3
Argumento / prova
Número grande + carimbo de estimativa + "baixar o porquê".
A4
Simulador
Input + resultado ao vivo + expander de memória de cálculo.
A5
Recap / revisão
Lista por seção + editar volta ao passo certo.
A6
Aceite (gate jurídico)
Leitura + botão único grande. Legal nunca atrás de expander.
A7
Espera
Estado + previsão honesta + aviso proativo.
A8
Painel / timeline
Etapas × estados. A máquina que o cliente assiste.
A9
Saída graciosa
1 template só: explica + captura lead + roteia + leva o dossiê junto.
A10
Erro recuperável
"Precisa de você" + ação concreta, dentro do pipeline.

Sistema

Governança — a parte que de fato mata

Governança de time é social; governança solo é mecânica. A regra não pode depender de lembrança. Fazer errado tem que ser mais difícil que fazer certo.

Regra dos 3

Nenhuma tela inventa componente — ou usa o que existe, ou promove conscientemente. Aparece nas 2 telas-farol → promove agora. Numa só → fica local, espera a 3ª ocorrência. Duas é coincidência; três é padrão.

Fundação larga, componente estreito

Cor, tipo, espaço, raio e motion valem pro produto inteiro — baratos de acertar agora. Componente só nasce quando uma tela pede. Zero componente especulativo.

Métrica (anti-guru: dá pra medir)

O queAlvo
valor hard-coded fora de token0
componentes novos por telacai ao longo das telas

Se a nona tela custar o mesmo que a primeira, o sistema falhou. O protótipo é colhido, não portado: migra decisão, não arquivo.
